Test environment support for file-storage EDI backends
(``edi_storage_oca``), on top of ``edi_core_oca_test_mode``.

When *Test mode* is enabled on a backend, every file operation —
polling, directory moves, sends and reads — resolves the test
counterparts instead of the live configuration:

- ``test_storage_id`` — an alternate ``fs.storage`` (different host,
  port, credentials)
- ``test_input_dir_*`` / ``test_output_dir_*`` — alternate directories,
  each falling back to its live counterpart when empty

The *Test environment* group on the backend Storage page holds these
fields and only appears for backend types with test mode supported.

Configuration
=============

1. Make sure the backend type has *Test Mode Supported* ticked (provided
   by ``edi_core_oca_test_mode``).
2. On the backend's Storage page, fill the *Test environment* group:

   - ``test_storage_id`` — only when test files live on a different
     SFTP/FS account; otherwise leave empty to reuse the live storage
   - ``test_*_dir_*`` — only the directories that differ from live
     (empty falls back to the live value)

3. Enable *Test mode* on the backend.

Usage
=====

With *Test mode* on, incoming files are polled from the test input
directory, outgoing files are written to the test output directory, and
done/error moves use the test directories — all on the test storage when
``test_storage_id`` is set. Toggling test mode off restores the live
configuration instantly; nothing is rewritten.
