This module adds a generic **test mode** to ``edi.backend``.

When enabled, the backend resolves test-specific connection parameters
instead of the live ones, so exchanges never reach live trading partners
by accident. Support is declared per backend *type* (*Test Mode
Supported* on ``edi.backend.type``); the backend form then shows a *Test
mode* toggle and a warning banner while active.

What "test" means is transport-specific: each connector whitelists the
parameters that have a test counterpart (``test_<name>`` fields) via
``_edi_test_conn_param_fields()`` and resolves them through
``edi.backend.get_conn_parameter()``.

``edi_storage_oca_test_mode`` provides the file-storage implementation
(test directories and an alternate test ``fs.storage``).

Copied or neutralized databases are safe by default:
``data/neutralize.sql`` enables test mode on every backend.

Configuration
=============

1. Open *EDI > Configuration > EDI Backend Types* and tick *Test Mode
   Supported* on the types whose transport offers a test environment
   (connector modules usually set this in their data).
2. Open the backend and enable *Test mode*. A warning banner reminds you
   exchanges will use the test configuration.
3. Fill in the transport-specific test parameters (e.g. the *Test
   environment* group provided by ``edi_storage_oca_test_mode``).

To extend test mode to your own parameters, whitelist the field names in
``_edi_test_conn_param_fields()`` and provide matching ``test_<name>``
fields; ``get_conn_parameter()`` resolves them automatically when test
mode is on, falling back to the live value when empty.

Usage
=====

Enable *Test mode* on a supported backend: all connection parameters
resolved through ``edi.backend.get_conn_parameter()`` switch to their
``test_`` counterparts. Disable it to return to the live configuration —
nothing is rewritten, so toggling is instant and safe.

Databases restored from a neutralized dump already have test mode
enabled on every backend.
